# Generated component producers call shared helpers in alef-component-abi

## Context and Problem Statement

Every native producer crate `alef` generated pasted the same support code into its `src/lib.rs`: an owned-buffer constructor and its `free` callback, an error-buffer helper, a panic-payload reader and, for async contracts, a task cancel/drop pair. The descriptor was a `static mut` only because it holds raw pointers and is therefore not `Sync`. The pasted code was not warning-free for every contract shape, so the file opened with `#![allow(clippy::missing_safety_doc, clippy::needless_borrow, unused_imports)]`, and consumers wrapped the generated host module in further blanket allows. Each consumer repository carried one copy of the helpers per producer crate, none of them tested where they lived.

## Decision Drivers

* Generated code should compile under a consumer's `-D warnings` without crate- or module-level lint allowances.
* Unsafe FFI glue should exist once, documented and tested, not once per generated crate.
* Producers already depend on `alef-component-abi` with an exact `=` pin (ADR 0015), so a helper there cannot drift from the generator that calls it.

## Considered Options

* Move the helpers into `alef-component-abi` as documented public items and have generated code call them.
* Keep pasting the helpers and fix their lints in the pasted text.
* Ship the helpers in a separate `alef-component-producer` support crate.

## Decision Outcome

Chosen option: "Move the helpers into `alef-component-abi`", because the crate is already the producer's only `alef` dependency, it is `no_std` plus `alloc` like the helpers, and the exact pin keeps generator and helper in lockstep.

The crate gains `SyncStatic<T>` (a `repr(transparent)` wrapper whose `unsafe` constructor makes an immutable pointer-carrying table usable as a plain `static`), `owned_buffer`, `free_owned_buffer`, `error_buffer`, `take_owned_bytes` (moved from `alef-component-runtime`, which re-exports it), `panic_message`, `cancel_flag_task` and the `construct_component!` macro. Generated producers import exactly the names their body uses, declare the descriptor as `static …: SyncStatic<AlefComponentV1>` and the function table as a plain `static`, and carry a `SAFETY` comment on every `unsafe` block. The generated host module drops its module-level `allow(dead_code)`; only optional catalog items (`COMPONENT_IDS`, `*_CONTRACT_HASH_HEX`, `host_target`, `component_manager`) carry a narrow `allow(dead_code)` with a reason.

### Consequences

* Good, because generated producers and host modules need no blanket lint allowances.
* Good, because the buffer and task ownership code is tested once in the ABI crate.
* Bad, because these items become part of the ABI crate's Rust API, which follows the `0.x` minor-release rule of ADR 0015.
* Bad, because producers generated by an older `alef` keep their pasted copies until regenerated.

### Confirmation

`src/codegen/component_producer.rs` and `src/codegen/component_host.rs` unit tests assert the generated text carries no module allowance, no `static mut`, a `SAFETY` comment on every `unsafe` block and only used imports. The ignored lanes `e2e_component_bytes_contract_test` and `e2e_component_producer_lint_test` run `cargo clippy -- -D warnings` on generated producers and on the generated host module, mounted privately and exported under `deny(missing_docs)`.

## Pros and Cons of the Options

### Helpers in `alef-component-abi`

* Good, because no new dependency is introduced.
* Bad, because the ABI crate's public surface grows.

### Keep pasting the helpers

* Good, because the ABI crate stays minimal.
* Bad, because every consumer keeps untested copies and the generator must keep each copy lint-clean for every contract shape.

### Separate support crate

* Good, because the ABI crate keeps only `repr(C)` types.
* Bad, because every producer gains a second pinned dependency that must move in lockstep.
