# File ownership by an embedded alef hash

## Context and Problem Statement

alef writes two kinds of files into a consumer repository: outputs it regenerates on every run, and starter files
(manifests, READMEs, sample tests) that a person is expected to edit afterwards. `alef verify` diffed the on-disk
content of generated files against a fresh render, so any external formatter run over them (php-cs-fixer, rubocop,
ruff, biome) produced false drift.

## Considered Options

* Embed an `alef:hash:<blake3>` line in every file alef owns, verify by comparing that hash with a fresh render, and
  leave unmarked files alone after creating them once
* Diff each generated file's on-disk content against a fresh render

## Decision Outcome

Chosen option: "Embed an `alef:hash:<blake3>` line in every file alef owns, verify by comparing that hash with a
fresh render, and leave unmarked files alone after creating them once", because the 0.8.3 release (748b905d4,
2026-04-26) made verify "a pure hash comparison" so that "External formatters ... can reformat the body freely
without ever causing a verify diff", and "Files without an alef hash header ... are skipped — alef has no claim over
them."

Later changes refined, not replaced, the rule:

* 3f8497139 (2026-08-14) made the marker itself the test: every file whose content carries an alef marker is
  stamped and verified, and `generated_header` only says whether a header is prepended.
* Unmarked files alef creates are create-once seeds: written only when absent, then user-owned. 86b1a7f16
  (2026-08-17) made `alef adopt` refuse them, and 779f7ba18 (2026-08-18) split overwriting them off `--clean`; both
  now need `--clobber-create-once-seeds`.

### Consequences

* Good, because consumers can run their own formatters over generated output, and verify still detects a stale
  file.
* Good, because a hand-grown manifest or test suite is never overwritten by a regeneration.
* Bad, because a create-once seed whose content goes stale is never updated by alef. `alef verify` reports it as
  "frozen path(s) DRIFTED" without failing, and the consumer must fix it by hand.
* Bad, because ownership hangs on a marker phrase ("generated by alef"), so a hand-written file that contains it,
  without a negation such as "not", is claimed.

### Confirmation

* `src/core/hash.rs:584` computes the per-file hash over the content with any `alef:hash:` line stripped, and
  `:643` injects the line after the header marker.
* `src/core/hash/markers.rs:11` defines the shared marker substring, and `src/core/hash.rs:297` the
  `content_has_alef_marker` test.
* `src/cli/pipeline/generate/scaffold.rs:225` documents scaffold files as create-only by default, and
  `src/bin_cli/args.rs:315` declares `--clobber-create-once-seeds`.
